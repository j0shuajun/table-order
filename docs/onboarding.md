# 온보딩 가이드 — 테이블오더 사용법

이 문서는 테이블오더를 **처음 실행하고 실제로 사용하는 방법**을 안내한다.
코드를 몰라도 따라 할 수 있도록 구성했다. 개발 환경 세팅 세부는
[개발 가이드](guide/development.md)를, 시스템 구조는
[아키텍처](guide/architecture.md)를 참고한다.

## 테이블오더는 무엇인가
식당의 태블릿 주문과 카운터/주방의 실시간 주문 관리를 제공하는 서비스다.
하나의 서버가 두 개의 화면을 서빙한다.

| 화면 | 주소 | 쓰는 사람 |
| --- | --- | --- |
| 고객 주문 앱 | `/` | 손님(테이블 태블릿) |
| 관리자 앱 | `/admin` | 사장님·직원(카운터/주방) |

## 1. 서버 실행하기
```bash
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000
```
- 최초 실행 시 데이터베이스(`table_order.db`)가 만들어지고 **데모 데이터가 자동
  입력**된다. 바로 사용해 볼 수 있다.
- 실행되면 브라우저에서 아래 주소로 접속한다.
  - 고객: `http://127.0.0.1:8000/`
  - 관리자: `http://127.0.0.1:8000/admin`

### 데모 계정
| 구분 | 값 |
| --- | --- |
| 매장 ID | `store001` |
| 관리자 | 아이디 `admin` / 비밀번호 `admin1234` |
| 테이블 | `T1`~`T6`, 비밀번호 모두 `0000` |

## 2. 관리자로 시작하기 (`/admin`)
카운터/주방에서 사용하는 실시간 관리 화면이다.

### 로그인
`/admin` 접속 → 매장 ID `store001`, 아이디 `admin`, 비밀번호 `admin1234` 입력.
로그인하면 상단에 **실시간 연결됨** 배지가 뜬다(신규 주문이 자동으로 들어온다는 뜻).

### 대시보드 (실시간 주문 현황)
- 테이블별 카드로 **현재 합계·주문 건수·최근 주문**을 한눈에 본다.
- 손님이 주문하면 해당 테이블 카드가 **약 30초간 강조**되고 알림이 뜬다.
- 카드를 클릭하면 상세 화면이 열린다.

### 주문 상세에서 할 수 있는 일
- **주문 상태 변경**: 접수 → 준비중 → 완료 (손님 화면에도 반영된다)
- **주문 삭제**: 잘못 들어온 주문 제거
- **이용 완료**: 손님이 나가면 누른다. 현재 세션이 닫히고 합계가 0으로 초기화되며,
  기록은 "과거 내역"으로 이동한다.
- **과거 내역**: 이 테이블의 지난 이용(닫힌 세션) 기록을 조회한다.

### 테이블 관리 탭
- 새 테이블을 **번호 + 비밀번호**로 등록한다(예: `T7` / 원하는 비밀번호).
- 등록된 테이블 목록을 확인한다.
- 각 테이블 행의 **"비밀번호 변경"** 버튼으로 기존 테이블의 비밀번호를 재설정한다
  (변경 즉시 기존 비밀번호는 무효).

### 관리자 비밀번호 변경
- 상단바의 **"비밀번호 변경"** 버튼 → 현재 비밀번호 확인 후 새 비밀번호 입력.
  다음 로그인부터 새 비밀번호를 사용한다.

### 메뉴 관리 탭
- **카테고리 추가**(예: 메인, 사이드, 음료)
- **메뉴 추가**: 이름·가격·카테고리를 지정(설명·이미지 URL은 선택)
- **가격 수정 / 메뉴 삭제**
- 변경은 손님 화면 새로고침 시 반영된다. (이미 접수된 주문은 주문 당시 가격이
  그대로 보존된다.)

## 3. 손님으로 주문하기 (`/`)
테이블 태블릿에서 사용하는 화면이다.

### 최초 1회 테이블 연결
태블릿을 설치할 때 한 번만: 매장 ID `store001`, 테이블 번호(예: `T1`),
비밀번호(`0000`)를 입력해 연결한다. 이후에는 자동으로 유지된다(약 16시간).

### 주문하기
1. **메뉴** 탭에서 원하는 메뉴의 **담기**를 누른다.
2. 하단 **장바구니**에서 수량을 조절한다(＋ / −).
3. **주문하기**를 누르면 주문번호와 합계가 표시된다.
4. **현재 주문** 탭에서 지금까지의 주문 목록과 상태(접수/준비중/완료), 세션 합계를
   확인한다.

## 4. 대표 시나리오 (전체 흐름)
```
손님(T1)이 태블릿에서 주문
        │
        ▼
관리자 대시보드의 T1 카드가 즉시 강조 + 합계/건수 증가 + 알림
        │
        ▼
직원이 "준비중" → "완료"로 상태 변경  ──▶  손님 "현재 주문" 탭에 상태 반영
        │
        ▼
손님 퇴장 → 직원이 "이용 완료"
        │
        ▼
세션 종료(합계 0으로 초기화) → 기록은 "과거 내역"으로 보관
```

## 5. 매장·계정·비밀번호 관리 (현재 지원 범위)
이 MVP는 **단일 매장 데모**로 설계됐다. 아래 표가 현재 실제로 가능한 것과
그렇지 않은 것을 정리한다.

| 하고 싶은 일 | 화면에서 되나? | 방법 |
| --- | --- | --- |
| 새 테이블 추가(원하는 비밀번호로) | ✅ 가능 | 관리자 앱 → "테이블 관리" → 번호·비밀번호 입력 후 등록 |
| 기존 테이블(예: `0000`) 비밀번호 변경 | ✅ 가능 | 관리자 앱 → "테이블 관리" → 해당 테이블 행의 "비밀번호 변경" 버튼 → 새 비밀번호 입력. 변경 즉시 기존 비밀번호 무효 |
| 관리자 본인 비밀번호 변경 | ✅ 가능 | 관리자 앱 상단바 "비밀번호 변경" → 현재 비밀번호 확인 후 새 비밀번호 입력 |
| 관리자 **아이디** 변경 | ❌ 불가 | 아이디 변경 화면·API가 없음. 지원하려면 개발 작업 필요 |
| 새 가게(매장) 등록 | ❌ 불가 | 매장은 `store001` 하나로 고정(설계 결정). 지원하려면 개발 작업 필요 |

### 참고
- 테이블·관리자 비밀번호는 모두 화면에서 바로 바꿀 수 있으므로 DB를 지울 필요가 없다.
- 관리자 **아이디**나 매장 자체를 바꿔야 한다면 시드 데이터(`app/seed.py`)의 값을
  수정한 뒤, 서버를 멈추고 `table_order.db`를 삭제하고 다시 실행하면 새 값으로
  초기화된다. **단, 기존 주문·이력도 함께 사라진다.** (시드는 매장이 이미 있으면
  건너뛰므로, DB를 지워야 새 시드가 적용된다.)

> "❌ 불가" 항목들(다매장, 관리자 아이디 변경)은 이번 MVP에서 의도적으로 범위 밖으로
> 둔 것이다. 필요하면 정식 기능으로 추가할 수 있다.

## 6. 환경 변수는 왜 필요한가
환경 변수는 **코드를 고치지 않고 실행 환경(로컬/데모/운영)마다 값을 다르게 주기
위한 설정**이다. 둘 다 선택 사항이며 기본값이 있어 그냥 실행해도 동작하지만,
운영에서는 조정이 필요하다.

| 변수 | 기본값 | 무엇이고 왜 필요한가 |
| --- | --- | --- |
| `TABLE_ORDER_JWT_SECRET` | 코드에 박힌 데모용 문자열 | 로그인 토큰을 서명하는 **비밀 키**. 기본값은 소스에 공개돼 있어 그대로 운영하면 누구나 위조 토큰을 만들 수 있다. **운영 전 반드시 32바이트 이상 무작위 값으로 교체**한다. |
| `TABLE_ORDER_DATABASE_URL` | `sqlite:///table_order.db` | 데이터를 저장할 **DB 위치**. 기본은 실행 폴더의 SQLite 파일 하나. 데이터 보관 경로를 옮기거나 다른 DB로 바꿀 때 지정한다. |

설정 방법은 두 가지다.

**방법 A — `.env` 파일 (권장)**: 저장소의 `.env.sample`을 복사해 값을 채운다.
```bash
cp .env.sample .env          # 편집기로 열어 값 입력
python -m uvicorn app.main:app --env-file .env --port 8000
```
`.env`는 커밋되지 않는다(`.gitignore`에 등록됨). 키는 아래처럼 생성한다.
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

**방법 B — 셸 export**:
```bash
export TABLE_ORDER_JWT_SECRET="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
export TABLE_ORDER_DATABASE_URL="sqlite:////var/data/table_order.db"
python -m uvicorn app.main:app --port 8000
```

## 7. 자주 묻는 상황
| 상황 | 확인/해결 |
| --- | --- |
| 관리자 화면에 신규 주문이 안 뜬다 | 상단 배지가 "실시간 연결됨"인지 확인. "재연결 중…"이면 잠시 후 자동 복구, 안 되면 새로고침 |
| 손님 화면이 "세션이 만료되었습니다"라고 함 | 약 16시간이 지난 것. 테이블 번호·비밀번호로 다시 연결 |
| 데모 데이터를 깨끗이 초기화하고 싶다 | 서버를 멈추고 `table_order.db` 파일을 삭제한 뒤 다시 실행 |
| 관리자/테이블 비밀번호를 바꾸고 싶다 | [5. 매장·계정·비밀번호 관리](#5-매장계정비밀번호-관리-현재-지원-범위) 참고 |
| 실제 운영에 쓰고 싶다 | [6. 환경 변수](#6-환경-변수는-왜-필요한가) 참고 — 특히 `TABLE_ORDER_JWT_SECRET` 교체 필수 |

## 참고
- 가격과 합계는 **항상 서버 기준**으로 확정된다. 손님 화면의 표시 가격을 조작해도
  실제 주문 금액은 서버 DB의 가격을 따른다.
- 한 테이블에는 진행 중인 세션이 **최대 1개**다. "이용 완료" 전까지의 모든 주문이
  한 세션(한 번의 방문)으로 묶인다.
