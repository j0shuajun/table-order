# U2 프론트엔드 결과

Written at (KST): 2026-09-07 22:20

## 왜 필요했나
U1에서 완성한 REST + SSE API를 실제 사용자가 쓸 수 있는 화면이 필요했다.
식당 태블릿의 고객 주문 화면과, 주방/카운터의 관리자 실시간 관리 화면을
붙여야 MVP가 "동작하는 서비스"로 완결된다.

## 무엇이 바뀌었나
FastAPI가 직접 서빙하는 순수 HTML/CSS/Vanilla JS 프론트엔드 두 벌을 추가했다.
빌드 단계 없이 `frontend/` 정적 파일을 U1이 정해 둔 URL(`/`, `/admin`,
`/static/*`)로 노출한다.

- **공용 계층** (`static/js/api.js`, `static/css/app.css`): 매장 ID, 토큰
  저장(localStorage), `request()` 래퍼(에러를 `ApiError`로 정규화),
  통화·시간 포맷 헬퍼와 공유 스타일.
- **고객 앱** (`index.html` + `customer.js`): 테이블 인증(태블릿 1회 설정) →
  카테고리별 메뉴 → 장바구니(수량 조절) → 주문 → 현재 주문/세션 합계 조회.
- **관리자 앱** (`admin.html` + `admin.js`): 관리자 로그인 → 테이블 대시보드
  (SSE 실시간) → 주문 상세 모달(상태 변경·삭제·이용 완료·과거 내역) →
  테이블 등록 및 메뉴/카테고리 CRUD.

## 최종 동작
### 고객 흐름
1. 저장된 테이블 토큰이 있으면 자동으로 메뉴 화면 진입, 없거나 만료(401)면
   인증 화면으로 폴백한다.
2. 메뉴를 담아 주문하면 서버가 확정한 주문번호·총액을 토스트로 알리고 현재
   주문 탭이 갱신된다. 가격/합계는 전적으로 서버 응답을 따른다.

### 관리자 흐름
1. 로그인 직후 대시보드를 불러오고 `EventSource(/api/admin/stream?token=)`로
   SSE에 연결한다. 연결 상태는 상단 배지로 표시한다.
2. 신규 주문(`order_created`) 수신 시 해당 테이블 카드를 약 30초간 강조하고
   토스트로 알린다. `order_updated`·`order_deleted`·`session_closed` 이벤트에서도
   대시보드와 열려 있는 상세 모달을 재로딩해 최신 상태를 유지한다.
3. 테이블 카드를 열면 진행 중 주문의 상태 변경(접수→준비중→완료), 삭제,
   이용 완료, 과거 내역 조회가 가능하다. 사용자 조작은 SSE와 별개로 즉시
   갱신도 트리거해 반응성을 확보한다.
4. 메뉴 관리 탭에서 카테고리 추가, 메뉴 추가, 가격 수정, 삭제를 처리한다.

## 대표 시나리오
- 태블릿 T1에서 주문 → 관리자 대시보드의 T1 카드가 즉시 강조되고 합계·건수가
  올라간다 → 관리자가 "준비중"으로 바꾸면 고객 현재 주문 탭에도 반영된다 →
  "이용 완료" 시 세션이 닫히고 과거 내역으로 이동, 대시보드 합계는 0으로 돌아간다.

## 현재 제약
- 단일 매장(`store001`) 기준. 다매장 전환/선택 UI는 범위 밖이다.
- 세션 만료 시 고객 앱은 비밀번호 재입력이 필요하다(무인 자동 재인증 없음).
- 이미지가 없거나 로드 실패한 메뉴는 placeholder 이미지로 대체한다.
- 검증은 실제 uvicorn 서버 대상 기능 스모크(로그인→주문→상태변경→완료→내역→
  메뉴 조회)로 응답 스키마 정합을 확인했다. JS는 no-build이므로 자동화 테스트
  대신 실행 경로 확인에 의존한다.
