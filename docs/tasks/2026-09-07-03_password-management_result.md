# 비밀번호 관리 기능 추가 (테이블·관리자)

Written at (KST): 2026-09-07 21:30

## 왜 필요했나
MVP 초기 설계는 테이블/관리자 비밀번호를 **시드 값으로 고정**했고, 값을 바꾸려면
DB를 지우고 재시드하는 방법밖에 없었다. 실제 운영에서는 기본 비밀번호(`0000`,
`admin1234`)를 그대로 두는 것이 부담이고, 데모 중에도 손쉽게 바꿀 수 있어야 한다.
단일 매장 고정이라는 기존 설계는 그대로 두면서, **화면에서 바로 비밀번호를 바꾸는**
두 가지 흐름을 추가했다.

## 무엇이 바뀌었나
1. **기존 테이블 비밀번호 재설정** — 관리자가 "테이블 관리" 탭에서 특정 테이블의
   비밀번호를 새로 지정한다. 변경 즉시 기존 비밀번호는 무효가 된다.
2. **관리자 본인 비밀번호 변경** — 로그인한 관리자가 현재 비밀번호를 확인받은 뒤
   새 비밀번호로 바꾼다.

두 기능 모두 백엔드 엔드포인트 + 관리자 화면 UI로 완결된다. 고객 앱은 변경하지 않았다.

## 동작 방식
- **테이블 비밀번호 재설정**: `PUT /api/admin/tables/{table_id}/password`
  `{ "password": "..." }` → `admin_service.reset_table_password`가 대상 테이블을
  찾아 새 bcrypt 해시로 교체한다. 공백 비밀번호는 400, 없는 테이블은 404.
- **관리자 비밀번호 변경**: `POST /api/admin/password`
  `{ "current_password": "...", "new_password": "..." }` →
  `auth_service.change_admin_password`가 현재 비밀번호를 검증(틀리면 401)한 뒤 새
  해시로 교체한다. 새 비밀번호가 공백이면 400.
- **화면**: 테이블 관리 탭의 각 테이블 행에 "비밀번호 변경" 버튼, 관리자 상단바에
  "비밀번호 변경" 버튼(모달로 현재/새 비밀번호 입력)을 두었다.

## 대표 시나리오
1. 관리자가 `T1`의 비밀번호를 `0000`에서 `9999`로 변경 → 태블릿이 `9999`로 재연결,
   `0000`은 더 이상 로그인되지 않음.
2. 관리자가 상단바에서 비밀번호를 `admin1234`→새 값으로 변경 → 다음 로그인부터 새
   비밀번호 사용, 기존 비밀번호는 401.

## 현재 제약
- 관리자 **아이디** 변경과 다매장은 여전히 범위 밖(단일 매장 고정 설계 유지). 아이디나
  매장을 바꾸려면 시드 수정 + DB 재시드가 필요하다.
- 비밀번호 정책(길이·복잡도)·로그인 시도 제한은 MVP 범위에 두지 않았다.
